# PHP 5.6 → 7.0

Read this file when the migration range includes PHP 7.0.

## Official sources
- https://www.php.net/manual/en/migration70.incompatible.php
- https://www.php.net/manual/en/migration70.deprecated.php
- https://www.php.net/manual/en/migration70.changed-functions.php
- https://www.php.net/manual/en/migration70.removed-exts-sapis.php
- https://github.com/php/php-src/blob/PHP-7.0/UPGRADING

## Breaking
- Many fatal errors are now thrown as `Error` (implements `Throwable`, not `Exception`). `catch (Exception $e)` no longer catches them, and a `set_exception_handler()` callback typed `Exception` breaks.
- Indirect access is now strictly left to right: `$$foo['bar']`, `$foo->$bar['baz']`, `$foo->$bar['baz']()`, `Foo::$bar['baz']()` change meaning. Use braces: `${$foo['bar']}`, `$foo->{$bar['baz']}`.
- `list()` no longer unpacks strings (use `str_split()`); empty `list()` is an error; `list($a[], $a[]) = …` assigns left to right.
- `foreach` no longer moves the internal array pointer. By-value iteration works on a copy; by-reference iteration sees appended elements.
- Hex strings are no longer numeric: `is_numeric("0x1A")` is false and `"0x1A" + 1` is 1.
- `\u{` in double-quoted strings and heredocs is a Unicode escape; a literal `\u{` needs `\\u{`.
- Integer handling: invalid octal literals (`0128`) are parse errors; negative bit shifts throw `ArithmeticError`; shifts ≥ the integer width give 0; `%` by zero throws `DivisionByZeroError`; `NAN`/`INF` cast to int are always 0.
- `substr()` / `iconv_substr()` return `""` instead of `false` when start equals the string length.
- Duplicate parameter names and several `default` blocks in one `switch` are compile errors.
- `func_get_args()`, `func_get_arg()`, `debug_backtrace()` report the current (modified) argument values.
- `$a = &new C;` is a parse error. `yield` is right-associative.
- Reserved class/interface/trait names: `bool`, `int`, `float`, `string`, `null`, `true`, `false`; soft-reserved: `resource`, `object`, `mixed`, `numeric`.
- `E_STRICT` notices were reclassified (static call of non-static method → `E_DEPRECATED`, incompatible signature → `E_WARNING`).
- JSON is now jsond: `34.`, `3.e3` and `""` are invalid JSON.
- `preg_replace()` `/e` modifier removed → `preg_replace_callback()`.
- `setlocale()` category must be an `LC_*` constant; `mktime()`/`gmmktime()` lost `$is_dst`.
- `<% %>`, `<%= %>`, `<script language="php">` tags removed; `$HTTP_RAW_POST_DATA` removed (use `php://input`); `#` comments in INI files removed.

## Removed
- Extensions: `ereg`, `mysql`, `mssql`, `sybase_ct`.
- Functions: `ereg*`, `split*`, `mysql_*`, `mssql_*`, `call_user_method()`, `call_user_method_array()`, `set_magic_quotes_runtime()`, `magic_quotes_runtime()`, `set_socket_blocking()`, `mcrypt_ecb()`, `mcrypt_cbc()`, `mcrypt_cfb()`, `mcrypt_ofb()`, `mcrypt_generic_end()`, `datefmt_set_timezone_id()`, GD Type1 `imageps*()`.

## Deprecated (removed in 8.0)
- PHP 4 style constructors (method named after the class, no `__construct`).
- Static calls to non-static methods.
- `password_hash()` `salt` option; `capture_session_meta` SSL option; `ldap_sort()`.

## Rector covers
Rector 2.7.0 set `php70` (17 rules):
- Fixes: `Php4ConstructorRector`, `EregToPregMatchRector`, `CallUserMethodRector`, `ExceptionHandlerTypehintRector` (`Exception` → `Throwable` in handlers), `ThisCallOnStaticMethodToStaticCallRector`, `WrapVariableVariableNameInCurlyBracesRector`, `EmptyListRector`, `ListSplitStringRector`, `ReduceMultipleDefaultSwitchRector`, `BreakNotInLoopOrSwitchToReturnRector`, `RenameMktimeWithoutArgsToTimeRector`, `MultiDirnameRector`.
- Modernisation: `IfIssetToCoalescingRector`, `TernaryToNullCoalescingRector`, `IfToSpaceshipRector`, `TernaryToSpaceshipRector`.
- **Skipped by default (risky):** `RandomFunctionRector` (`rand()` → `random_int()`, a CSPRNG that throws on bad ranges).

## Tools miss — review manually
- `mysql_*` → `mysqli`/PDO: no Rector rule. Rewrite by hand; parameter order and connection handling differ.
- `catch (Exception …)` that should also catch `Error`: decide per site whether to catch `Throwable`.
- Code relying on `foreach` moving the array pointer (`current()`/`next()`/`reset()` inside loops).
- `=== false` checks on `substr()` results.
- Arithmetic or `is_numeric()` on hex strings.
- Sorting tests that assert the order of equal elements.

## Grep patterns
Regexes are ripgrep syntax (usable with the Grep tool). Review every hit; a hit is a place to look, not proof of a bug.

- `\bmysql_[a-z_]+\(` — removed extension
- `\b(ereg|eregi|split|spliti)(_replace)?\(` — removed functions
- `preg_replace\(\s*['"](.).*\1[a-zA-Z]*e[a-zA-Z]*['"]` — `/e` modifier
- `catch\s*\(\s*\\?Exception\b` — does not catch `Error`
- `\$\$[a-zA-Z_]+\[` and `->\$[a-zA-Z_]+\[` — indirect access order
- `list\(\s*\)` — empty `list()`
- `substr\(.*\)\s*===?\s*false` — now `""`
- `0x[0-9a-fA-F]+['"]` — hex numeric strings
- `\\u\{` — Unicode escape
- `function\s+(\w+)\s*\(` in `class \1` — PHP 4 constructor
- `set_exception_handler` — `Throwable` handler
